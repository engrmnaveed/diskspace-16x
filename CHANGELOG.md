# Changelog

## Unreleased

- Name the Settings switches, the free-space threshold menu and the Save Footprint Receipt fields for VoiceOver, which read them without a label before.
- Install the CLI with Cargo: releases publish the `diskuse16x` crate to crates.io, so `cargo install diskuse16x` builds Basic and `--features pro` builds Pro. `cargo install --git https://github.com/engrmnaveed/diskuse16x diskuse16x --locked` builds the newest code.
- Install the Mac app with one command: `install.sh --app` downloads the release ZIP with curl, checks its SHA-256 checksum and signature, and installs **DiskUse16x.app** into `~/Applications` without an admin password. curl adds no quarantine flag, so the app opens on its first launch without the **Open Anyway** step. Running it again updates the app, and `--uninstall --app` removes it.
- Move the repository to `engrmnaveed/diskuse16x`. GitHub redirects the old address. The install one-liners now run the attested `install.sh` from the latest release instead of a pinned commit, so they always match that release's archives.
- Rename Space 16X to **DiskUse16x**. The command is now `diskuse16x`, with `du16x` installed beside it as a short name, and `--version` prints `diskuse16x X.Y.Z`. Release archives are `diskuse16x-TARGET.tar.gz` and `diskuse16x-pro-TARGET.tar.gz`. The installer moves to `~/.local/share/diskuse16x` and replaces a `space16x` command it installed earlier, with its shell setup, while keeping an executable you replaced. Nothing you saved is lost: `SPACE16X_READ_ONLY` still works when `DISKUSE16X_READ_ONLY` isn't set, exports with `space16x_` keys still open, and Pro keeps using a scan history in `$XDG_STATE_HOME/space16x/history` when it's the only one. New exports use `diskuse16x_` keys.
- Rename the Mac app to **DiskUse16x** (`DiskUse16x.app`, bundle ID `com.16xbrains.diskuse16x`, `diskuse16x-X.Y.Z-macos-universal.zip`). On its first launch it copies Space 16X's settings, such as Pro features, excludes and the menu-bar monitor, and it keeps using a history in `~/Library/Application Support/Space 16X/History` when that's the only one. The Homebrew cask is now `diskuse16x`, and `brew upgrade` moves the `space16x` cask to it. macOS sees a new app, so turn on Full Disk Access for DiskUse16x again if you use it.
- Promise a stable CLI for 1.x. `docs/cli.md` and `docs/cli-pro.md` say that within 1.x, commands and options, exit codes, JSON schema 3, the export format and Pro's scan history change only by additions. A breaking change waits for 2.0 and a new `schemaVersion`.
- Find updates from the Mac app. **Help → Check for Updates…** opens the newest release's page in your browser, and **Help → DiskUse16x Help** opens the user guide. The app still never connects to the network itself. `docs/install.md` and the guide's FAQ say how to update each way you can install DiskUse16x.
- Install the CLI with Homebrew on macOS and Linux. The `engrmnaveed/tap` tap adds the formulas `du16x` (Basic) and `du16x-pro` (Pro) beside the Mac app's cask, and each release updates all three. Run `brew install engrmnaveed/tap/du16x` after `brew tap engrmnaveed/tap` and `brew trust engrmnaveed/tap`.
- Install the CLI on Linux from a `.deb` or `.rpm` package. Each release attaches `diskuse16x_amd64.deb`, `diskuse16x_arm64.deb`, `diskuse16x.x86_64.rpm` and `diskuse16x.aarch64.rpm`, and the same four for Pro as `diskuse16x-pro…`, built from the static Linux executables, with SHA-256 files and attestations. They install `/usr/bin/diskuse16x` and `/usr/bin/du16x`, and installing one edition's package replaces the other with apt, or with dnf's `--allowerasing`. The packages aren't signed, so dnf notes that it skipped OpenPGP checks, and zypper needs `--allow-unsigned-rpm`.
- Add a user guide in `docs/guide` for people new to DiskUse16x. It has a two-minute quick start for the Mac app and one for the terminal, then pages on finding what uses space, cleaning up safely, saving and sharing scans, Pro, and common questions, with screenshots and GIFs of the real app and CLI. Two captioned walkthroughs are on YouTube: the Mac app at https://youtu.be/34wE80c-4d0 and the terminal at https://youtu.be/5aBSDL4HIuo. The README links the guide near the top.

Move to Trash takes files, not folders, while the filter is on, since folders may hold newer files.

## 0.8.0

- See the space a scan can't show in Space 16X Pro. `space16x explain [PATH]` shows the size, used and free space of PATH's volume. On macOS it adds each volume of the APFS container with its own used space (the system volume, Preboot, VM, Recovery and your data), purgeable space that macOS frees when needed, and Time Machine local snapshots. On Linux it adds the blocks reserved for root and the deleted files that programs still hold open, with each program's name and process ID. `--json` writes the same figures. In the Mac app, with **Settings → Pro features** on, **Scan → Explain Disk Space** (⇧⌘X), or a volume's context menu on the start screen, shows them for the volume. It reads system figures and metadata only.
- Find folders you can safely clear in Space 16X Pro. `space16x scan --cleanup` lists folders that tools recreate when they need them, such as `node_modules`, Cargo's `target`, Xcode's DerivedData and device support files, simulator caches, `Library/Caches`, `.cache` and the Gradle and npm caches, largest first, and `--json` writes them as `suggestions`. Press `u` in the CLI explorer for the same list, then Space and `d` to move folders to the Trash after you confirm. In the Mac app, with **Settings → Pro features** on, **Cleanup** in the sidebar (or **Browse → Cleanup Suggestions**, ⌘6) lists them for Move to Trash. Suggestions come from names in the finished scan, and nothing is removed without your confirmation.
- See what deleting would actually free in Space 16X Pro. `space16x scan --exclusive` adds an **Exclusive** column, and `exclusiveBytes` in JSON: the space that moving an item to the Trash and emptying it frees at least, without blocks it shares with APFS clones or Btrfs and XFS reflinks, and without files that have other hard links. In the Mac app, with **Settings → Pro features** on, the Move to Trash confirmation says how much emptying the Trash frees at least when clones or hard links share some of the space.
- Find duplicate files in Space 16X Pro. `space16x duplicates [PATH]` lists files with the same contents, grouped, with the space the extra copies use, and `--json` writes the groups. It compares only files of 1 MB or more (`--min-size`) that share a length, reading their first 64 KB and then whole files. In the Mac app, with **Settings → Pro features** on, **Duplicates** in the sidebar (or **Browse → Duplicates**, ⌘7) lists the copies for Move to Trash after you click **Find Duplicates**. This is the only feature that reads file contents, and only when you ask.
- See a folder as a treemap in the CLI explorer of Space 16X Pro. Press `m` to draw the open folder's contents as boxes in proportion to their size, with the selection highlighted, and `m` again for the list.
- Share a scan as a web page in Space 16X Pro. `space16x scan --html FILE` also writes one self-contained HTML page with the totals, a treemap of the largest items, the scan root's contents, the largest files, file types and, on shared servers, owners. It has no scripts, loads nothing and follows light or dark mode. `--html -` writes only the page to standard output.
- Watch free space from the menu bar in Space 16X Pro on the Mac. **Settings → Pro features → Show free space in the menu bar** shows the startup disk's free space in the menu bar, with every volume's free space in its menu, and posts one notification when free space drops below the threshold you pick (10 GB by default, or never). It checks once a minute while it's shown and does nothing when it's off.
- Save Build Footprint receipts in Space 16X Pro on the Mac. While comparing with a saved scan, **Scan → Save Footprint Receipt…** or the receipt button beside the comparison asks what you measured, such as "first Xcode build", and saves a Markdown receipt: both scan times, the totals and item counts, what files gained and lost, and the largest file changes, with paths relative to the scanned folder. It notes partial scans and comparisons of different folders.
- Open several windows in Space 16X Pro on the Mac. **File → New Window** (⌘N) opens a window with its own scan, so you can browse two folders or disks side by side, and the menus act on the window in front.
- Move the Pro commands' reference to `docs/cli-pro.md`, which only the Pro archive ships, so Basic's archive stays small. `docs/cli.md` keeps everything Basic does, the exit codes and JSON schema 3.
- Refresh the promo Short and the README preview to show Pro's cleanup suggestions in the CLI and the Mac app's Duplicates.

## 0.7.0

- See when files last changed in Space 16X Pro. The CLI explorer adds a **Modified** column with each item's newest modification date, a folder's being the newest of any file inside, and JSON reports add `newestModified` in Unix seconds. `space16x scan --older-than DAYS` counts only files last modified more than DAYS days ago, so sizes, rankings and top files show where old data sits. In the Mac app, with **Settings → Pro features** on, the folder list and Largest Files add a sortable **Modified** column. Pro reads the times with the same metadata calls as sizes, keeps them in a side table beside the scan tree, and Basic's memory and output are unchanged.
- See which file types use the most space in Space 16X Pro. `space16x scan --types N` lists the N largest types by extension with their size and file count, then the rest in one line, and `--json` writes them as `types`. Press `t` in the CLI explorer for the open folder's types. In the Mac app, with **Settings → Pro features** on, **Types** joins List, Treemap and Donut (or **Browse → File Types**, ⌘5). Both apps group files the same way: `Clip.MOV` and `clip.mov` are `.mov`, and `.bashrc` has no extension.
- See who fills a shared server in Space 16X Pro. `space16x scan --by-owner` lists the space and items each user owns, largest first, and `--json` writes them as `owners` with each `uid` and user name.
- Keep a scan history in Space 16X Pro. `space16x history save PATH` keeps a scan in `$XDG_STATE_HOME/space16x/history` (by default `~/.local/state/space16x/history`), `space16x history` lists the kept scans, and `space16x history diff PATH [--since DAYS]` shows what changed since the newest kept scan, or since the newest one at least DAYS days old. In the Mac app, **Save to History** (⌥⌘S, or from **Compare…**) keeps the results in `~/Library/Application Support/Space 16X/History`, and **Compare…** and **Scan → Compare with History** list the folder's saved scans. Only an explicit save writes anything, and kept scans are ordinary exports that `--import`, `diff` and **Open Scan…** read.
- Refresh the promo Short to show Pro's file-type report in the CLI and the Mac app's Compare with a saved scan and the **Modified** column.

## 0.6.0

- Save a scan and browse it later or on another computer. `space16x scan --export FILE` saves the whole scan in ncdu's JSON format, and `--export -` writes it to standard output. `space16x --import FILE` or `--import -` opens it in the explorer, read-only, so `ssh -C server space16x scan / --export - | space16x --import -` scans a server and browses the result locally. ncdu and gdu open these exports, and Space 16X opens theirs. Without a terminal, `--import` prints the one-level report.
- Save and open scans in the Mac app. **File → Export Scan…** (⇧⌘E) saves the results in the same ncdu JSON format as the CLI, and **File → Open Scan…** (⇧⌘O) or dropping a `.json` file opens a scan saved by the app, the CLI, ncdu, or gdu. Opened scans are read-only: Rescan, Quick Look, Reveal in Finder, and Move to Trash are off until you scan a folder again.
- See which disk is filling up with `space16x volumes`: size, used and free space, use percentage, and inode use for each mounted volume, in text or with `--json`. It leaves out memory filesystems, snap images, bind mounts and macOS system volumes unless you pass `--all`. The Mac app's start screen lists your volumes with their free space, and clicking one scans it.
- Add Space 16X Pro, a second free edition built from the same source. The CLI's `pro` Cargo feature builds it, and each release publishes `space16x-pro-<target>.tar.gz` beside the Basic archive for all four targets. `install.sh --pro` installs Pro over Basic, and installing without it switches back. `space16x --version` ends with `(pro)` and JSON reports say `"edition": "pro"`. In Basic, a Pro command such as `space16x diff` prints a one-line hint to install Pro. The Mac app stays one app, with **Settings → Pro features**, off by default.
- Compare scans in Space 16X Pro. `space16x diff OLD NEW|PATH` compares a saved scan with another one, or with a folder scanned now using the saved scan's exclude patterns, and lists what grew or shrank one level down. `--depth N` goes deeper, `--top N` lists the files that changed most, including added and removed ones, and `--json` writes schema 3. In the Mac app, with **Settings → Pro features** on, **Compare…** above the folder list (or **Scan → Compare with Saved Scan…**, ⇧⌘K) adds a **Change** column, sortable by change, with the folder's total change and the items removed since then.
- Build the CLI with full link-time optimization and one codegen unit, which keeps the release archives smaller than 0.5.0's with export and import added. Scan speed is unchanged.
- Fix a trailing slash after the scan root in the total line of text reports, which 0.5.0 added.
- Refresh the promo Short to show a server's scan piped into the CLI explorer and the Mac app's Compare.

## 0.5.0

- Scan faster with less memory in the CLI. Scans read metadata on several threads, one per core up to 8, and `--threads N` sets the count for `scan` and the explorer. Use `--threads 1` on hard disks and network filesystems. Every thread count gives the same report. On macOS, the scanner reads each folder's file metadata in a single bulk call, so a 1,000,000-file scan takes about 1.2 seconds instead of 5.5. The scanner keeps each file's name instead of its full path, which cuts peak memory by more than half. The JSON schema and exit codes are unchanged. Issues are now listed in path order.
- Scan faster with less memory in the Mac app. The scanner reads several folders at once, up to 8, and a 1,000,000-file folder takes about 2.3 seconds instead of 5.6. Scanned items keep their names and share their folder's path instead of each storing a full path, which cuts peak memory by about two thirds. Results don't depend on the order folders finish in, including which path counts a hard-linked file.

## 0.4.0

- Move files and folders to the Trash from the CLI explorer. Press Space to mark items, press `d`, and confirm the count and size with `y`. Folder totals and rankings update in place without a rescan. Space is freed when you empty the Trash. On Linux, items go to the FreeDesktop.org Trash that file managers use, and they are never copied to another disk. `--read-only` or `SPACE16X_READ_ONLY=1` turns trashing off. Cloud-only, protected, and incompletely scanned items stay where they are.
- Move files and folders to the Trash from the Mac app. Select one or more rows with ⌘-click or ⇧-click, then press ⌘⌫, choose **Browse → Move to Trash…**, use the row's context menu, or click **Move to Trash** in the selection bar. An alert confirms the item count and allocated size. The list, charts, and totals update in place without a rescan. Cloud-only, protected, unscanned, and incompletely read items stay where they are, as in the CLI explorer.
- Rescan one folder without rescanning everything. Press `r` in the CLI explorer, or choose **Scan → Rescan Folder** (⌥⌘R) or **Rescan Folder** in a folder's context menu in the Mac app. The new results replace that folder in place, and the totals and item counts above it update. Exclude patterns keep applying relative to the scanned folder. Cancelling keeps the earlier results.
- Preview the selected file or folder with Quick Look in the Mac app. Press Space, or choose **Browse → Quick Look** (⌘Y) or **Quick Look** in the context menu. The preview follows the selection, as in Finder, and Space closes it. Cloud-only items aren't previewed, because that would download them.

## 0.3.0

- Add apparent sizes and item counts to the CLI. `space16x scan --apparent` shows and ranks file lengths, as `ls -l` reports them, instead of allocated bytes, which helps with sparse and compressed files. JSON reports move to schema 3, which keeps every schema 2 field and adds `apparentBytes`, `itemCount` (files and folders below an entry, counting each hard-linked file once), `rankedBy` and `edition`. Exit codes are unchanged.
- Skip files and folders by pattern in the CLI explorer and reports with `--exclude PATTERN` and `--exclude-from FILE`. Patterns follow a small `.gitignore` subset: `node_modules` or `*.log` match a name anywhere, `/build` anchors to the scan root, `**` spans folders, and `cache/` matches folders only. Excluded entries aren't read, keep the scan complete, and appear as `excludedCount` and `excludes` in JSON.
- Sort the CLI explorer's folder contents by size, item count, or name with `s`, and switch between allocated and apparent sizes with `a`. Wide terminals show an Items column, and file details show both sizes. The explorer honors `NO_COLOR` and a new `--no-color` option.
- Sort the Mac app's folder list and Largest Files by name, size, or item count from the column headers, with a new Items column. **View → Size** switches the tables, charts, and totals between allocated and apparent sizes and remembers the choice. **Settings → Exclude from scans** takes the same patterns as the CLI, one per line, and the header and Scan Details report how many items were excluded.
- Refresh the promo Short and the README preview to show the Mac app's sortable folder list with item counts.

## 0.2.4

- Treat folders the system won't let apps read as protected items rather than scan errors. A scan of `/` used to show an orange "Partial scan" with hundreds of skipped paths, though nearly all were expected macOS restrictions. Both apps now keep the orange warning for real errors and show a neutral notice for protected items. The Mac app groups them by folder in Scan Details and offers Full Disk Access when it would unlock some of them. The CLI summarizes them in one stderr line and marks them `[protected]` and Protected in the explorer. JSON output and exit codes are unchanged.
- Show CLI sizes in decimal units (KB, MB, GB), the way Finder, System Settings, and the Mac app do, instead of binary KiB, MiB, and GiB. The same folder now shows the same number everywhere, for example 245.33 GB rather than 228.5 GiB. The CLI explorer's file details and the Mac app's size tooltips also show the binary size next to the exact byte count. JSON reports are unchanged and still give exact bytes.
